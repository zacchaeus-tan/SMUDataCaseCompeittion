# Lives Group synthetic dataset

All data is **synthetic**, generated by `scripts/generate_data.py` (seed 2026; re-running gives identical files).
Customer, vendor and people names are fictional, except *National University Hospital*, which the brief uses as its example.
State this in the report as an assumption: *"No client data was provided, so we built a synthetic dataset
whose structure mirrors SAP B1 master data and purchase-order exports."*

```bash
python3 scripts/generate_data.py
```

## Planted patterns (what your analysis should find)

The ground truth is in `data/answer_key/`. **Use it only to score your methods, never as model input.**

**Master data problems**
- **41 duplicate customer records (17%)** across 205 real customers. There are two kinds:
  - *Migration*: someone couldn't find the existing record and created a new one, and all later orders go there. **The old record looks like a customer who stopped ordering, but isn't.**
  - *Entity split*: another entity created its own record for the same customer, so one product's orders are booked there. **This makes a customer that buys A and B look like two customers, one buying only A and one buying only B, which creates false cross-sell gaps.**
  - Name variants include abbreviations, typos, upper case, missing legal suffixes and "Centre"/"Center". About half the duplicates have a blank registration number.
  - National University Hospital has three records: `National University Hospital`, `National Univ. Hospital (S) Pte Ltd` and `NUH`.
- **Duplicate item:** `A-1009` repeats `A-1001` (the dengue test). From Dec 2025, Thai and Vietnamese orders for it are booked under A-1009, so **A-1001 appears to decline in TH/VN when it hasn't**.
- **3 duplicate vendors**, each created by a second entity.

**Commercial patterns**
- **Growth set by country** (annual volume, A/B/C): VN fastest (+28/+22/+15%), ID (+18/+20/+8%), MY (+10/+8/+3%), TH (+6/+12/+2%), SG flat for A/B and declining for C (−10%).
- **Seasonality:**
  - Dengue season raises Product A demand (SG/MY/TH Jun–Sep, VN Jul–Oct, ID Jan–Apr).
  - Hospital budgets are spent at year end (Nov +5%, Dec +15%) with a lull in January.
  - Holiday dips: Lunar New Year, Tet, Songkran, Hari Raya/Lebaran.
- **19 customers genuinely dropping off (9%):** volume falls from early 2026, some to zero. In Vietnam, three of the largest Product B buyers are among them, which hides Vietnam's strong underlying growth.
- **16 new customers** start ordering partway through the period. Each has a matching request in `mdm_requests_history.csv`.
- **Cross-sell gaps:** customers who buy A but not B (and vice versa), listed in `answer_key/true_customers.csv`.

**Process baseline (today's email workflow)**
- Median **18.8 days** from request to SAP record (mean 19.6). **41% bounce back** at least once.
- Actual working time is **0.4%** of the elapsed time; the rest is waiting.
- Where the time goes: approval queues **62%**, MDM triage **15%**, requestor rework **12%**, keying into SAP **10%**.
- Some requests create the very duplicates above (`answer_key/mdm_requests_flags.csv`).

**Inbound messages (for sorting orders from enquiries)**
- 300 orders, 230 enquiries, 70 follow-ups and 60 setup/change requests. About 30% of the non-Singapore messages are in Bahasa Indonesia, Malay, Thai or Vietnamese.
- Deliberately tricky cases:
  - Orders that never say "purchase order" ("as per your quotation, please supply…")
  - Enquiries that mention ordering ("we are planning to order next quarter…")
  - Follow-ups that quote an existing PO number
  - Internal setup requests sent to the sales mailbox

## Growth measure (recommended)

- **Main measure:** year-on-year unit growth, **Apr–Sep 2026 vs Apr–Sep 2025**, by country × product. Comparing the same months removes the seasonal effects.
- **Momentum:** the last 3 months vs the same 3 months a year earlier.
- **Product C (equipment):** volumes are small and lumpy (about 30–50 units per country per half-year), so report it on a rolling 12 months or in SGD value.
- **Count customer orders only.** Enquiries, follow-ups and setup requests are not demand.

## Assumptions to state in the report

- The entity → product mapping, all names, prices and growth rates are illustrative.
- Each requestor, approver and customer is synthetic. The roles in `sharepoint/Roles.csv` stand in for real approvers.
- Approval timings are calibrated to the brief: 2–3 weeks, and Amy's 18 days.
